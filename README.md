# FPV Drone Arena — лабораторна робота №5

## Запуск
Треба Node.js 18 або новіший.

```bash
npm install
npm start
```

Відкрий http://localhost:3000 у двох вкладках/вікнах. W/↑ — газ, A/D або стрілки — поворот, Space — постріл. Чат доступний унизу.

## Реалізовано
- Спільний детермінований модуль `shared/sim.js`, фіксований `dt = 1/30`, власний seeded PRNG; без `Math.random()` і `Date.now()` у симуляції.
- Серверний авторитетний світ; клієнт надсилає input із `seq`, а не координати.
- Серверний цикл на 30 кроків/с із плануванням за цільовим часом, без `setInterval`.
- Клієнтське передбачення та повтор непідтверджених input.
- Буфер станів інших гравців з інтерполяцією на 100 мс.
- Бінарні input/snapshot через `ArrayBuffer`/`DataView`, little-endian, версія протоколу та кут `Int16`.
- Перемикач JSON для порівняння, netgraph: RTT, вік знімка, байти/с, черга input і поправка.
- Чат збережено у цій демонстраційній реалізації.

## JSON проти binary
| Ознака | JSON | Binary |
|---|---|---|
| Розмір | Зазвичай більший через ключі та текстові числа | Компактні поля фіксованої довжини |
| Кодування | Легко читати й налагоджувати | Потрібна схема полів і версія |
| CPU/мережа | Парсинг тексту, більше байтів | Менше байтів, DataView |
| Розширення | Простіше додавати поля | Потрібно узгоджувати схему |

## Експеримент і висновки
Запустіть два вікна та порівняйте рух при перемиканні JSON/binary. Для вимірювання затримки можна використати DevTools Network throttling або інструмент мережевого проксі. Занотуйте RTT, вік знімка та поправку передбачення. Збільшення RTT/втрати пакетів збільшує розбіжність між передбаченим і серверним станом. Сервер не приймає координати від клієнта, тому підміна позиції не дає клієнту прямого контролю над світом. Для чужих кораблів використовується затримка інтерполяції 100 мс як компроміс між плавністю та затримкою відображення.
